# 1.3 Research Questions

## 1.3.1 Sensor Fusion for False Alarm Discrimination

The primary challenge in modern fire safety is the prevalence of unwanted alarms triggered by non-combustion aerosols, such as steam, cooking fumes, or cleaning sprays, which frequently deactivate automated detection systems [1]. While traditional single-modality detectors struggle with these "nuisance" triggers, multi-sensor data fusion—integrating particulate smoke, Volatile Organic Compounds (VOC), Carbon Monoxide (CO), and infrared flame signatures—offers a mathematically robust framework for optimal sensor integration under uncertainty [2]. Empirical evidence suggests that multi-sensor frameworks can reduce false alarms by up to 73% compared to conventional single-sensor systems [2]. This study evaluates whether a specific array of MEMS-based gas sensors and infrared detectors can reliably distinguish between active combustion and ambient environmental variances. Consequently, the first research question asks: _Can a multi-sensor fusion approach effectively discriminate between real fire events, normal ambient conditions, and common indoor false alarm triggers?_ This inquiry specifically focuses on the separability of multi-modal data in a stationary node context, targeting the identification of unique combustion signatures that remain distinct from household aerosols.

## 1.3.2 Real-Time TinyML Constraints on Cortex-M4 Platforms

Deploying sophisticated machine learning models on resource-constrained microcontrollers necessitates a rigorous balance between classification accuracy and execution speed [3]. The Cortex-M4 architecture, while widely adopted for its Digital Signal Processing (DSP) support, operates at lower clock frequencies than standard edge processors, such as the 48MHz Renesas RA4M1 utilized in the Arduino UNO R4 [3]. For fire detection systems to be considered safe for real-world application, inference latency must typically remain below 100ms to ensure near-instantaneous response times [3]. Existing research indicates that achieving such low latency often requires intensive model optimization, including quantization and pruning, to fit within the limited RAM and Flash memory of embedded devices [1]. This study seeks to determine the technical feasibility of running a fully integrated neural network on this low-power hardware without exceeding critical processing thresholds. Therefore, the second research question is: _Is TinyML deployment on a 48MHz Cortex-M4 microcontroller feasible for real-time fire detection while maintaining an inference latency of less than 100ms?_

## 1.3.3 Evaluation of Three-Class versus Binary Classification

Current fire detection literature is largely dominated by binary classification models that categorize events simply as "fire" or "no-fire" [1]. Such binary frameworks often lack the granularity to handle complex non-fire scenarios, frequently grouping false alarm triggers with either the fire class (leading to false positives) or the no-fire class (leading to high variance in the "normal" baseline) [1]. Advanced TinyML strategies now advocate for multi-class paradigms, where explicit "false alarm" labels allow the model to learn the specific statistical patterns of culinary activities or chemical sprays [3]. By providing the model with a dedicated class for nuisance triggers, it is hypothesized that the precision of the actual "fire" classification will improve significantly. This comparison is vital for understanding whether the increased complexity of a three-class model translates into tangible reliability gains in domestic and industrial environments. Thus, the third research question investigates: _How does three-class classification (fire/no_fire/false_alarm) compare to traditional binary classification in reducing false positive rates for intelligent fire detection nodes?_

### Glossary

- **Inference Latency**: The time required for a deployed machine learning model to process an input and generate a classification output on the edge device.
- **Quantization**: A model optimization technique that converts high-precision weights (e.g., 32-bit float) to lower-precision formats (e.g., 8-bit integer) to reduce memory usage and increase inference speed.
- **Three-Class Classification**: A supervised learning approach that categorizes data into three distinct labels—in this context, identifying fire, normal background, or non-fire nuisance events.
- **TinyML**: A field of machine learning focused on deploying optimized models on low-power, resource-constrained microcontrollers at the hardware edge.
